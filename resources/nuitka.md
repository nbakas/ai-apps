> The free version of Nuitka will not include Commercial code-protection features such as data hiding, traceback encryption, or encrypted stderr.

> In any case, a determined attacker may still reverse-engineer compiled code; Nuitka increases the effort but does not make reverse engineering impossible.


Run a Docker container with same Python version as used in development.

```powershell
docker run --rm -it -v "${PWD}:/work" -w /work python:3.12-slim bash
```

Install build tools required by Nuitka's C compiler backend.

```bash
apt-get update && apt-get install -y --no-install-recommends build-essential
```

Install Nuitka.

```bash
python -m pip install Nuitka
```

```bash
python -m nuitka --version
```

Make module.

If you want to include specific packages in the module build, use the following option:

```bash
--follow-import-to=package1,package2 \
```

> Note that package1, package2 are folders with Python code and should contain an `__init__.py` (usually empty) file to be recognized as Python packages.


```bash
python -m nuitka app.py \
    --module \
    --python-flag=isolated \
    --python-flag=no_docstrings \
    --python-flag=no_asserts
```

This will generate an app*.so file, like:

```text
app.cpython-312-x86_64-linux-gnu.so
```

Exit the Docker container.
```bash
exit
```

Finally, use a wrapper script (e.g., `runapp.py`) to run your module. Call `runapp.py` in your Dockerfile.

```python
from app import main
main()
```

Python automatically recognizes: `app.cpython-312-x86_64-linux-gnu.so` as module `app`. Keep `runapp.py` and the `.so` in the same directory.

The generated `app.pyi` is a type stub generated by Nuitka for IDEs and type-checking tools. You can delete `app.pyi`. It is not needed at runtime or in your production container.
